Privacy & security

MIRAGE processes prompts with local rules in your browser. It has no analytics, account, remote scanner, or prompt API. This notice applies to the 1.1.2 release candidate.

Where your data goes

Original drafts, token mappings, passphrases, and restored replies stay inside the MIRAGE page or extension side panel. When you click Insert into chat, only the preview you approved is given to the supported chatbot page. Insertion itself makes that preview accessible to the website, even before you press Send.

The Get latest reply button reads the latest supported assistant response from the connected page. Restoration happens only in MIRAGE. The extension does not place your original details into the chatbot’s page.

Hosted web workspace

The hosted version serves app files through Vercel. Your prompt text is processed in your browser and is not submitted to the hosting service by MIRAGE. Vercel can receive ordinary page-request metadata such as IP address and browser information. The Chrome extension runs from its packaged files. No analytics are installed in either version.

Permissions

sidePanel opens MIRAGE beside your chat. activeTab and scripting support tab discovery and the user-requested insert/read actions. ChatGPT and Gemini are declared as optional site permissions. MIRAGE asks for access only to the site you select when you click Connect current chat; Disconnect removes that site grant. The adapter accepts only those exact HTTPS origins. There are no install-time host permissions, background browsing monitors, or page message listeners.

Session lifetime

Up to 20 scans are kept in memory so you can restore earlier replies. Closing or reloading the workspace clears its mappings. MIRAGE also clears the session after 15 minutes without an action in MIRAGE. A suspended browser may delay timers; expiry is checked again when you return or use a control.

Clear session removes the app’s references, not forensic traces from computer memory. It does not erase your operating system clipboard, downloaded files, browser downloads history, or data you already shared.

Encrypted backups

Saving a backup is optional and explicit. It contains token mappings and scan timestamps, not full drafts or replies. The backup uses AES-256-GCM with a random salt and IV, and PBKDF2-SHA256 with 600,000 iterations. Your passphrase is not stored. Use a long, unique passphrase and keep it separately. There is no recovery service.

Backups remain sensitive: anyone who has both the file and passphrase can unlock them. Browser extensions with broader permissions, malware, or someone using your unlocked device are outside MIRAGE’s protection.

Detection limitations

Local rules can miss names, addresses, unusual secrets, obfuscated data, or language-specific formats. Aadhaar gets a checksum check; PAN, UPI, and IFSC get format checks, not identity verification. Medical details are preserved unless you explicitly mask them. A scan with no matches is not a privacy guarantee.

Write your draft in MIRAGE first. Text typed into another website is already available to that website. Files, images, voice, native chatbot editors, and unsupported websites are outside protection.

Release status

This is a release candidate for controlled testing, not an independently audited DLP product. Chatbot interfaces change; unsupported layouts stop with a manual-copy fallback. Review every preview and the final chatbot draft. Live provider compatibility and a security review remain release gates.
